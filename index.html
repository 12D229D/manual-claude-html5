Introducción a Claude Code

#
Claude Code es la herramienta de línea de comandos oficial de Anthropic para integrar a Claude en tu flujo de desarrollo. Funciona como un agente de IA que puede leer, escribir, editar y ejecutar código en tu repositorio.

¿Qué es Claude Code?

Claude Code es un agente de codificación autónomo que vive en tu terminal. A diferencia de los asistentes de código tradicionales, Claude Code puede:

  • Leer y comprender toda tu base de código
  • Crear, editar y eliminar archivos
  • Ejecutar comandos de shell (tests, builds, lint, git)
  • Navegar por el historial de git y hacer commits
  • Usar herramientas MCP para acceder a servicios externos
  • Delegar tareas a subagentes especializados

Instalación

# Instalación global
npm install -g @anthropic-ai/claude-code

# Verificar instalación
claude --version

# Actualizar
npm update -g @anthropic-ai/claude-code
# Linux/macOS
curl -fsSL https://claude.ai/install.sh | sh

# Windows (PowerShell)
irm https://claude.ai/install.ps1 | iex

# Verificar
claude --version
# Imagen oficial
docker pull anthropic/claude-code:latest

# Ejecutar en directorio actual
docker run -it --rm \
  -v $(pwd):/workspace \
  -v ~/.claude:/home/node/.claude \
  anthropic/claude-code:latest

Autenticación

Claude Code requiere una cuenta de Anthropic con acceso a la API:

# Iniciar sesión (abre navegador)
claude auth login

# Ver estado de autenticación
claude auth status

# Cambiar cuenta
claude auth logout && claude auth login

Primeros pasos

  1. Navega a tu proyecto: cd mi-proyecto
  2. Inicia Claude Code: claude
  3. Escribe tu primera tarea en lenguaje natural
Tip: Usa Ctrl+C para interrumpir una tarea en curso. Usa Ctrl+D o /exit para salir.

Conceptos clave

ConceptoDescripción
SesiónUna conversación continua con contexto compartido
ContextoArchivos leídos, comandos ejecutados, historial de chat
HerramientasAcciones que Claude puede realizar (Read, Write, Bash, etc.)
PermisosControl de qué herramientas puede usar Claude (allow/deny)
SubagenteAgente especializado para tareas específicas (testing, research, etc.)

# Sesión interactiva normal

CLAUDE.md — Instrucciones del proyecto

Archivo markdown que proporciona contexto persistente a Claude sobre tu proyecto. Se carga automáticamente al iniciar una sesión en el directorio.

Ejemplo completo de CLAUDE.md

# Instrucciones para Claude Code - Mi Proyecto

## Contexto del Proyecto
Este es un **API REST en Node.js/TypeScript** con Express y PostgreSQL.
Arquitectura: Clean Architecture + DDD.

## Stack Tecnológico
- **Runtime**: Node.js 20+ (ESM)
- **Framework**: Express 4 + TypeScript 5
- **DB**: PostgreSQL 15 + Prisma ORM
- **Testing**: Vitest + Supertest
- **Lint**: ESLint + Prettier + TypeScript strict
- **CI**: GitHub Actions

## Estructura de Directorios
src/
├── domain/          # Entidades, value objects, domain events
├── application/     # Use cases, DTOs, ports (interfaces)
├── infrastructure/  # Implementaciones: DB, HTTP, external APIs
├── presentation/    # Controllers, routes, middleware, schemas
└── shared/          # Utils, constants, errors, types

## Convenciones de Código
- **Naming**: camelCase (vars/funciones), PascalCase (tipos/clases), UPPER_SNAKE_CASE (constantes)
- **Imports**: Agrupados: node_modules → @/ → relativos. Usar alias @/ para src/
- **Error handling**: Never throw; usar Result o Option
- **Async**: Siempre async/await, nunca .then().catch()
- **Tests**: Co-located *.test.ts al lado del archivo. AAA pattern.

## Comandos Útiles
```bash
npm run dev          # Desarrollo con hot reload
npm run build        # Compilar TypeScript
npm run test         # Tests unitarios + integración
npm run lint         # ESLint + Prettier check
npm run db:migrate   # Prisma migrate deploy
npm run db:studio    # Prisma Studio
```

## Patrones del Proyecto
- **Use Cases**: Una clase por caso de uso en application/
- **Repositories**: Interfaces en domain/, impl en infrastructure/
- **Validation**: Zod schemas en presentation/schemas/
- **Auth**: JWT en middleware, refresh tokens en httpOnly cookies

## Qué NO hacer
- ❌ No usar any (usar unknown + type guards)
- ❌ No acceder a DB directamente en controllers
- ❌ No poner lógica de negocio en middleware
- ❌ No commitear .env ni secrets

## Contexto Adicional
- Base de datos: esquema en prisma/schema.prisma
- Variables de entorno: ver .env.example
- API docs: Swagger en /api-docs (dev only)
- Logs: pino pretty en dev, JSON en prod

Orden de precedencia

PrioridadFuenteÁmbitoPersistencia
1 (más alta)Flags CLI (--allowedTools, --model, etc.)Sesión actualTemporal
2.claude/settings.local.jsonProyecto (local)Persistente (gitignored)
3.claude/settings.jsonProyecto (compartido)Persistente (committed)
4~/.claude/settings.jsonUsuario (global)Persistente
5 (más baja)Defaults de Claude CodeSistemaBuilt-in

Agentes y Subagentes

#

¿Qué son los subagentes?

Los subagentes son instancias especializadas de Claude que se delegan tareas específicas. Cada subagente tiene su propio contexto, herramientas permitidas y prompt de sistema personalizado.

Agentes built-in

AgentePropósitoHerramientas típicas
general-purposeTareas generales de investigación y análisisRead, Glob, Grep, Bash, WebSearch
code-reviewerRevisar código por calidad, seguridad, bugsRead, Glob, Grep, Bash
test-writerEscribir tests unitarios e integraciónRead, Write, Edit, Bash
debuggerDepurar errores, traces, logsRead, Bash, Grep, Glob
refactorerRefactorizar código legacyRead, Write, Edit, Bash
documenterGenerar documentación técnicaRead, Write, Glob, Grep

Crear subagentes personalizados

Los subagentes se definen en .claude/agents/.md:

---
name: "api-designer"
description: "Diseña APIs REST/GraphQL siguiendo mejores prácticas"
tools: ["Read", "Write", "Edit", "Glob", "Grep", "Bash"]
model: "opus"
---

# API Designer Agent

Eres un experto en diseño de APIs. Tu trabajo es:

1. **Analizar requerimientos** y proponer endpoints RESTful
2. **Definir contratos** con OpenAPI/Swagger
3. **Validar** consistencia, versionado, paginación, errores
4. **Generar** código boilerplate (controllers, schemas, types)

## Principios de Diseño
- Recursos sustantivos, no verbos: GET /users no GET /getUsers
- Versionado en URL: /v1/users
- Paginación: cursor-based para colecciones grandes
- Errores: RFC 7807 Problem Details
- Rate limiting headers: X-RateLimit-*

## Output Esperado
- Archivo OpenAPI 3.1 (yaml)
- Types TypeScript (Zod + inferred types)
- Controllers Express con validación
- Tests de contrato básicos

Usar subagentes (delegación)

# Desde la CLI interactiva
> Usa el agente api-designer para crear la API de pagos

# O con la herramienta Task directamente
> /agent api-designer "Crea endpoints para procesar pagos con Stripe"

# Listar agentes disponibles
> /agents

AGENTS.md — Instrucciones para agentes

Archivo que define cómo deben comportarse los agentes en tu proyecto (similar a CLAUDE.md pero para subagentes):

# AGENTS.md - Instrucciones para Subagentes

## Reglas Globales para Todos los Agentes
- Seguir CLAUDE.md del proyecto
- Usar TypeScript strict, sin any
- Tests obligatorios para código nuevo
- Commits convencionales (feat:, fix:, refactor:)

## Agentes Especializados

### code-reviewer
- Revisar: seguridad, performance, DX, testing
- Bloquear PR si: no hay tests, hay any, lint falla
- Sugerir mejoras con ejemplos de código

### test-writer
- Cobertura mínima: 80% statements, 70% branches
- Tests: unitarios (vitest), integración (supertest)
- Mocks: solo para external APIs, no para DB

### refactorer
- Preservar comportamiento observable
- Extraer funciones puras
- Eliminar duplicación (DRY)
- Actualizar tests afectados

Mejores prácticas

  • Un agente, una responsabilidad — No crear agentes "todo en uno"
  • Prompt de sistema claro — Define objetivo, constraints, output format
  • Herramientas mínimas — Principio de menor privilegio
  • Modelo apropiado — Haiku para tareas simples, Opus para razonamiento complejo
  • Versionar agentes — Guardar en git como parte del proyecto

Skills (Habilidades)

#

¿Qué son las Skills?

Skills son paquetes reutilizables que extienden las capacidades de Claude Code. Cada skill incluye prompts de sistema, herramientas permitidas, y lógica para tareas específicas. Son similares a "plugins" pero más ligeros y enfocados.

Estructura de una Skill

.claude/skills/
└── mi-skill/
    ├── SKILL.md          # Manifiesto (requerido)
    ├── prompts/          # Prompts de sistema
    │   └── system.md
    ├── scripts/          # Scripts auxiliares (opcional)
    │   └── helper.js
    └── templates/        # Plantillas (opcional)
        └── component.tsx

SKILL.md — Manifiesto

---
name: "react-component-generator"
version: "1.0.0"
description: "Genera componentes React con TypeScript, tests y stories"
author: "tu-usuario"
tags: ["react", "typescript", "frontend", "generation"]
tools: ["Read", "Write", "Edit", "Glob", "Grep", "Bash"]
model: "sonnet"
---

# React Component Generator Skill

Genera componentes React siguiendo las convenciones del proyecto.

## Uso
```
/skill react-component-generator "Crea un componente Button con variantes"
```

## Qué genera
- Componente principal (Button.tsx)
- Tests (Button.test.tsx)
- Storybook (Button.stories.tsx)
- Estilos (Button.module.css)
- Export en index.ts

## Convenciones que sigue
- Props con interface + tipo discriminado para variantes
- ForwardRef obligatorio
- classNames con clsx/tailwind-merge
- Accesibilidad (ARIA, focus-visible)
- Tests: render, interacción, snapshot visual

Descubrimiento y carga

Las skills se descubren en este orden:

  1. ~/.claude/skills/ — Usuario (global)
  2. .claude/skills/ — Proyecto (compartido)
  3. .claude/skills.local/ — Proyecto (local, gitignored)

Comandos de skills

# Listar skills disponibles
/skill list

# Cargar una skill
/skill load react-component-generator

# Ejecutar skill con parámetros
/skill react-component-generator "Button con loading state"

# Ver detalles de una skill
/skill info react-component-generator

# Crear nueva skill (interactivo)
/skill create mi-nueva-skill

Ejemplo: Skill para Code Review Automatizado

---
name: "auto-code-review"
version: "1.2.0"
description: "Revisa PRs automáticamente: seguridad, performance, DX"
author: "equipo-plataforma"
tags: ["review", "security", "performance", "ci"]
tools: ["Read", "Glob", "Grep", "Bash"]
model: "opus"
---

# Auto Code Review Skill

Ejecuta revisión completa de un PR o rama.

## Prompt de Sistema (prompts/system.md)
```
Eres un Senior Staff Engineer revisando código.
Enfócate en:
1. **Seguridad**: SQLi, XSS, secrets, authz, crypto
2. **Performance**: N+1, memory leaks, bundle size, DB indexes
3. **DX**: naming, types, error handling, logging
4. **Testing**: coverage, edge cases, flaky tests

Formato de salida: Markdown con secciones 🔴 Crítico 🟡 Advertencia 🟢 Sugerencia
Incluye archivo:línea para cada hallazgo.
```

## Uso en CI
```yaml
- name: Auto Code Review
  run: |
    claude -p "/skill auto-code-review HEAD~1..HEAD" \
      --allowedTools Read,Glob,Grep,Bash \
      --model opus
```

Mejores prácticas

  • Naming: kebab-case para nombre de carpeta y skill
  • Versión: SemVer en SKILL.md
  • Tools mínimas: Solo las necesarias
  • Documentar: README.md en la skill con ejemplos
  • Testear: Probar con /skill info

Slash Commands

#

¿Qué son los Slash Commands?

Los Slash Commands son comandos personalizados que se ejecutan dentro de la sesión interactiva de Claude Code escribiendo / seguido del nombre del comando. Permiten automatizar flujos de trabajo repetitivos.

Estructura

.claude/commands/
├── nombre-comando.md       # Comando simple
└── namespace/
    └── subcomando.md       # Comando con namespace

Formato del archivo de comando

---
name: "create-feature"
description: "Crea una nueva feature completa: código, tests, docs"
arguments:
  - name: "feature-name"
    description: "Nombre de la feature (kebab-case)"
    required: true
  - name: "type"
    description: "Tipo: component, api, hook, page"
    required: false
    default: "component"
---

# Create Feature Command

Crea una feature completa siguiendo las convenciones del proyecto.

## Pasos
1. Validar que no existe ya
2. Crear estructura de archivos
3. Generar código boilerplate
4. Crear tests básicos
5. Actualizar exports/index
6. Ejecutar lint + tests para verificar

## Argumentos
- : nombre en kebab-case (ej: user-profile)
- [type]: component | api | hook | page (default: component)

## Ejecución
```
> /create-feature user-profile component
> /create-feature payment-api api
```

Comandos con namespace

.claude/commands/
├── deploy.md
└── db/
    ├── migrate.md
    ├── seed.md
    └── studio.md

# Uso

> /db:seed
> /db:studio

Hooks

#

¿Qué son los Hooks?

Los Hooks son scripts que se ejecutan automáticamente en puntos específicos del ciclo de vida de Claude Code. Permiten automatizar validaciones, logging, notificaciones, y modificaciones de comportamiento sin cambiar el código principal.

Tipos de Hooks

EventoCuándo se ejecutaCasos de uso
preToolUseAntes de ejecutar cualquier herramientaValidar inputs, logging, bloquear operaciones peligrosas
postToolUseDespués de ejecutar una herramientaLogging, métricas, notificaciones, auto-formateo
notificationCuando Claude envía notificación al usuarioSonido, desktop notification, webhook a Slack/Discord
stopCuando la sesión termina (exit, compact, error)Cleanup, guardar estado, métricas de sesión
userPromptSubmitCuando el usuario envía un promptValidar prompt, inyectar contexto, rate limiting
sessionStartAl iniciar una nueva sesiónCargar contexto, verificar config, health checks
preCompactAntes de compactar el contextoGuardar información importante, backup

Configuración en settings.json

{
  "hooks": {
    "preToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo '🔧 Ejecutando: $TOOL_INPUT' >> ~/.claude/hooks.log"
          },
          {
            "type": "command",
            "command": "node .claude/hooks/validate-bash.js '$TOOL_INPUT'"
          }
        ]
      },
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "node .claude/hooks/auto-format.js '$TOOL_INPUT'"
          }
        ]
      }
    ],

MCP (Model Context Protocol)

#

¿Qué es MCP?

Model Context Protocol (MCP) es un estándar abierto que permite a Claude Code conectarse a servidores externos para acceder a datos, herramientas y recursos. Funciona como "plugins" pero con un protocolo estandarizado basado en JSON-RPC 2.0.

Configuración de servidores MCP

En settings.json (user o project):

{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:pass@localhost:5432/db"
      }
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/allowed/dir"]
    },
    "custom-server": {
      "command": "python",
      "args": ["/path/to/mcp-server.py"],
      "env": { "API_KEY": "${CUSTOM_API_KEY}" }
    }
  }
}

Crear servidor MCP personalizado (Python)


# mcp-server.py
# pip install mcp[cli]

from mcp.server import Server
from mcp.server.models import InitializationOptions
from mcp.types import Tool, TextContent
import asyncio

server = Server("mi-servidor-personalizado")

@server.list_tools()
async def list_tools() -> list[Tool]:
    return [
        Tool(
            name="saludar",
            description="Saluda a alguien",
            inputSchema={
                "type": "object",
                "properties": {
                    "nombre": {"type": "string", "description": "Nombre a saludar"}
                },
                "required": ["nombre"]
            }
        ),
        Tool(
            name="obtener_datos",
            description="Obtiene datos de mi API interna",
            inputSchema={
                "type": "object",
                "properties": {
                    "endpoint": {"type": "string"},
                    "params": {"type": "object"}
                },
                "required": ["endpoint"]
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    if name == "saludar":
        return [TextContent(type="text", text=f"¡Hola, {arguments['nombre']}! 👋")]
    
    if name == "obtener_datos":
        # Llamada real a tu API
        import httpx
        async with httpx.AsyncClient() as client:
            resp = await client.get(f"https://api.miempresa.com/{arguments['endpoint']}", params=arguments.get('params'))
            return [TextContent(type="text", text=resp.text)]
    
    raise ValueError(f"Herramienta desconocida: {name}")

async def main():
    from mcp.server.stdio import stdio_server
    async with stdio_server() as (read, write):
        await server.run(read, write, InitializationOptions(
            server_name="mi-servidor",
            server_version="1.0.0",
            capabilities=server.get_capabilities()
        ))

if __name__ == "__main__":
    asyncio.run(main())

Troubleshooting MCP

Problemas comunes

  • Servidor no conecta: Verifica que el comando existe en PATH. Usa rutas absolutas.
  • Timeout: Aumenta timeout en settings: "mcpTimeout": 60000
  • Permisos: El proceso heredado debe tener permisos para leer/env vars.
  • Variables de entorno: Usa ${VAR} en settings.json, se expanden al iniciar.
  • Stdout/stderr: El servidor MCP debe usar stdout solo para JSON-RPC. Logs a stderr.

Troubleshooting & FAQ

#

Errores comunes y soluciones

Error: "Authentication failed" / "Invalid API key"

Causas y soluciones:

  1. Ejecutar claude auth logout && claude auth login
  2. Verificar que la cuenta tiene acceso a la API de Anthropic
  3. Si usas ANTHROPIC_API_KEY, verificar que es válida y no ha expirado
  4. Comprobar conectividad de red / proxy corporativo
Error: "Tool use blocked by permissions"

La herramienta está en la lista deny o no está en allow.

# Ver permisos actuales
claude config get permissions

# Permitir herramienta temporalmente
claude --allowedTools Bash,Write

# O en settings.json
{
  "permissions": { "allow": ["Read", "Write", "Edit", "Bash", "Glob", "Grep", "Task"] }
}
Error: "MCP server failed to start" / "Connection refused"
  1. Verificar que el comando existe: which npx o ruta absoluta
  2. Probar manualmente: npx -y @modelcontextprotocol/server-github
  3. Verificar variables de entorno (tokens, URLs)
  4. Revisar logs: claude --verbose 2>&1 | grep -i mcp
  5. Aumentar timeout: "mcpTimeout": 60000 en settings.json
Error: "Context window exceeded" / Respuestas truncadas

El contexto de la sesión es demasiado grande.

  • Usar /compact para resumir historial
  • Usar /clear para limpiar completamente
  • Dividir tarea en sesiones separadas
  • Usar --disallowedTools para limitar herramientas que generan mucho output
Error: Hooks lentos / Timeouts en herramientas

Los hooks se ejecutan en CADA invocación de herramienta.

  • Hooks deben completarse en < 100ms
  • Evita I/O de red/disco en hooks preToolUse
  • Usa postToolUse para operaciones pesadas
  • Deshabilita hooks problemáticos temporalmente: "hooks": { "preToolUse": [] }
Error: "Command not found: claude" tras instalar

El binario no está en PATH.

  • npm: npm root -g → agregar a PATH
  • Reiniciar terminal / shell
  • Usar npx claude-code como alternativa

FAQ Rápida

¿Puedo usar Claude Code offline?
No. Requiere conexión a la API de Anthropic.
¿Cuánto cuesta?
Basado en tokens consumidos (input + output). Ver /cost en sesión. Modelos: Opus > Sonnet > Haiku.
¿Mis datos se usan para entrenar?
No. Anthropic no usa datos de API para entrenar (según su política de privacidad).
¿Funciona en Windows?
Sí. WSL2 recomendado para mejor compatibilidad con herramientas Unix.
¿Puedo compartir configuración del equipo?
Sí. Commit .claude/settings.json, CLAUDE.md, AGENTS.md, .claude/commands/, .claude/agents/ al repo.
¿Cómo actualizar?
claude update o npm update -g @anthropic-ai/claude-code
¿Soporta otros modelos (GPT, local)?
No oficialmente. Solo modelos de Anthropic (Opus, Sonnet, Haiku).
